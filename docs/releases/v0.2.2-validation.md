Validated on Windows on 2026-09-24. This is a new pre-release; v0.2.1 and its
published assets are not replaced or retagged.

- Packaging, source-bundle, resource and secret-safety tests: **22 passed**.

  Bash was added only to the test process PATH for the shell-query tests.
- All **35** installed packaging requirements match the pinned build lock;
  dependencies are unchanged from v0.2.1. Python: 3.13.2, Windows x64.
- PyInstaller and Inno Setup completed successfully. Installer:
  `Moltage-Setup-0.2.2.exe`, **64,047,803 bytes**,

- PyInstaller reported the optional `pycparser.lextab` / `pycparser.yacctab`

- The bundled update log, GPL text, notices and **35 license files** match the

  absent; `opengl32sw.dll` is retained. Packaging tests verify embedded OpenSSL,

- All **29** third-party source archives passed their pinned SHA256 checks and
  were rebuilt into the v0.2.2 corresponding-source bundle.

with isolated empty APPDATA/LOCALAPPDATA and software OpenGL. Its main window,
About dialog (0.2.2, Junfeng Lin, GPL-3.0-only), and license-notices viewer opened
successfully. Normal window closure terminated the process; stderr was empty.

No real profiles, credentials, remote projects or HPC connections were used.
This does not replace fresh-machine UAC install/upgrade/uninstall acceptance.

Both manuals were rebuilt: English **63 pages**, Simplified Chinese **58 pages**.

those pages. Manual edits are synchronized; generated PDFs remain release
attachments rather than tracked source files.

## Independent review and publication boundary

A read-only Claude review of the proposed source tree reported **no release
blockers**. It did not execute tests or verify real HPC compatibility. Its
non-blocking findings are retained rather than described as fixed:

- Forward-written project schema 12 and preference schema 3 are not downgrade
  compatible with v0.2.1. Release notes now require backups and warn against
  mixed application versions on updated records. The old preference reader's
  schema rejection was also checked directly at tag v0.2.1.
- Import cancellation after directory allocation may leave a reported partial
  destination requiring manual inspection.
- Imported custom/per-element basis overrides are not fully interpreted;
  automatic basis mapping should not be used for those inputs. Method/basis/
  dispersion recognition is limited to supported keyword evidence.
- Import validation reads and server checksum acquisition are separate; import
  only completed directories that will remain unchanged during the operation.
- Server checksum failures remain explicit refresh failures, not a fallback to
  downloading large wavefunctions.
- TXT export is specific to ORCA WBL and contains numeric columns; retain the
  accompanying result JSON for model/parameter provenance.
- The synthetic report image has a minor annotation/curve intersection; this is
  not numerical data corruption. The stable model ID is preserved.

Targeted staged-tree checks found no known private infrastructure identifiers,
high-confidence credential tokens/private-key blocks, runtime state files or
redistributed scientific-program data. The only Cube fixture is covered by the
synthetic-fixture declaration. The new report screenshot and legacy-result
fixtures each have explicit synthetic provenance. This review does not claim a
fresh independent audit of all historical Git objects or legal certainty.

Existing completed OpenSpec apply validations are reused because their artifacts
are unchanged; no archive or new feature implementation was performed for this
release. Publication uses a normal new commit/tag and a source ZIP from that exact
commit, never an archive of the dirty working directory. Local build, review,
runtime and PDF output directories are excluded from Git.
