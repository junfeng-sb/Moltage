# Architecture

## Status and intent

This document records the target architecture. Phase 3A, Phase 3B, UI-M2, UI-M2-R1, and UI-R3 are fully accepted and frozen. Phase 3C retains the frozen Phase 1 molecular/junction/viewer layers, Phase 2A optimization input generation, accepted Phase 2B identity/security/submit-once behavior, Phase 2C recovery, Phase 2D electrode construction, Phase 3A Step-3 input science, and Phase 3B completion/surface/tcontrol science. Step 4 uses a separately verified AITRANSS runtime through the existing durable submission boundary. Phase 4A/4B retain their typed failures, electrode-provenance partitioning, installed-compatible layer selection, immutable attempt history, and reader-compatible external self-energy grammar. Phase 4C adds only positive Step-4 result classification and strict non-spin `TE.dat` parsing with the supported grammar and success markers. Phase 4C-R1 remains downstream of that frozen boundary and adds only deterministic logarithmic result presentation, raw-linear `T(EF)` annotation, and local axis editing. UI-R4 changes only local runtime presentation ownership: multiple live Geometry and Transmission work objects now coexist as tabs without changing any frozen scientific or remote boundary. UI-R5 adds narrow MOL V2000 import plus display-only single/double/triple strands while preserving every frozen scientific and remote boundary. NOTIFY-M1 remains optional profile-owned Slurm-native terminal mail metadata. Periodic monitoring, automatic or bulk cancellation, conductance/current analysis, export/analysis frameworks, and arbitrary Step-4 retry remain outside this boundary. REMOTE-R3-R1 adds only an explicitly confirmed exact-job cancellation for a current Step-3 parent that remains `RUNNING` while its authoritative current-attempt output reproduces the reviewed task-OOM evidence. The task-restart extension adds a separate explicitly confirmed right-click action for the exact current `QUEUED` or `RUNNING` Step 1–4 task; it prepares an editable draft from hash-verified pre-run inputs and never performs automatic cancellation or resubmission.

The later user-approved current-view exporter is a narrow exception to that earlier generic export-framework exclusion: it captures only existing presentation pixels and introduces no data transform, comparative analysis, project persistence, or remote operation.

UI-R6 adds only application-session visualization preferences and renderer filtering. UI-R6-R1 adds a modal live-preview transaction for those preferences and the existing inferred-connectivity factor. It does not change domain, scientific, project, persistence, Transmission, or remote boundaries.

The atom-feedback refinement is **fully accepted and frozen**. It adds only theme-owned, presentation-only atom hover and density-fragment ring/number overlays to the shared molecular viewer; the immutable domain structure, Connectivity, Cube scalar fields, density partition, and all local/remote calculation boundaries remain unchanged.

Standalone local `.next_step` import is fully accepted and frozen. It changes only local extension-dispatched loading: the selected file is complete input to the existing molecular-geometry parser, while server-backed optimized-structure recovery and its two-file chemistry-consistency checks remain unchanged.

PM-R1 changes only Project Manager presentation and project-list management. One read-only presentation adapter over recovery snapshots supplies sorting and the Details, Compact, and Tiles renderers; it is never workflow authority. Local recycle tombstones remain non-authoritative current-machine metadata, while permanent deletion is isolated behind one narrow exact-project remote boundary. No project-manifest schema, scheduler/scientific classification, workspace identity, submission, recovery, or notification behavior changes.

Local Tight-Binding Transmission, including the separate result window and hover-only parameter feedback refinement, is **fully accepted and frozen**. It is an independent, session-local calculation surface. It snapshots the active molecular structure and Connectivity, performs no SSH/Slurm/AITRANSS operation, writes no project or user setting, and does not alter the frozen Step 1–4 workflow.

The Slurm/LSF scheduler boundary and evidence-directed runtime-discovery workflow are **fully accepted and frozen** for the 0.1.6 release. Scheduler-specific resource models remain separate, while every operation for one task retains its selected scheduler. LSF is accepted only after its complete client directory bundle initializes through read-only `lsid`; no server-specific setup script, recursive filesystem scan, or packaged path is part of this boundary.

## Dependency direction

The primary dependency direction is:

`GUI -> Application -> Domain`

The application layer may invoke infrastructure adapters through narrow boundaries. Domain code must not depend on GUI frameworks, SSH libraries, Slurm commands, email transports, or filesystem accidents. Infrastructure may translate external systems into domain/application concepts, but it must not own scientific workflow policy.

Visualization consumes immutable domain structures and connectivity. Domain and structure modules do not depend on PySide6, VTK, or visualization code.

## Desktop entry and packaged resources

`moltage_gui.py` is the thin packaging entry and delegates to the accepted desktop `main()` without duplicating GUI startup behavior. Immutable icons and scientific resources are resolved only through `app/package_resources.py`, which distinguishes the source resource root from a frozen bundle root without consulting the current working directory. Per-user profiles, known hosts, project metadata, credentials, and logs remain outside those bundled resources under their existing application-data and secret-store owners. Application-owned density manifests and recovered payloads use `%APPDATA%\Moltage\density_results`, resolved by `app/paths.py` independently of the process current working directory.

The desktop-theme surface is **fully accepted and frozen**. `gui/theme.py` owns the application-level theme registry and immutable theme definitions. `future_light` / **Future Light** remains the backward-compatible default, joined by the approved Light themes `arctic_circuit`, `pearl_quantum`, `aurora_glass`, and `solar_paper`, plus the Dark themes `event_horizon` and `ember_lab`. Each definition supplies one centralized Qt palette, generated application stylesheet, restrained spacing/radius/tab tokens, dark-aware tab-close asset, and the first available Windows font from `Segoe UI Variable` then `Segoe UI`. Generic processing and recovery progress bars use the same borderless 6 px track, so dialogs do not independently choose incompatible thicknesses. The Theme popup is one widget-backed two-column selector with separate Light/Dark headers, header rules, and a central divider while retaining the existing exclusive actions and per-user registered-ID persistence. Neutral SVG toolbar/menu icons are retinted from the active theme's primary text color whenever the theme changes; multicolor measurement/editing icons instead use paired light/dark resources so rotation, deletion, and replacement semantics are not flattened. Both paths preserve logical geometry, and the tinted path preserves the source device-pixel ratio so high-DPI switching cannot shrink icons. General widget colors and states therefore do not belong in individual dialogs; dynamic scientific swatches and custom-painted workflow-state indicators remain with their existing renderers. The native Windows window frame and controls remain unchanged.

The current theme refinement changes only the widget-backed chooser indicator: unchecked choices are hollow circles and the checked choice is the same circle with a centered theme-accent dot. Theme repolishing snapshots and restores a normal top-level `QRect`, including one deferred restoration after layout polish, so the first runtime theme change cannot resize or move the main window. Maximized, minimized, and full-screen window states are never replaced by that normal-geometry path.

The Windows x64 distribution is a PyInstaller one-folder, windowed application wrapped by a UAC-elevated Inno Setup installer. Setup always shows the destination-directory page, defaults to `{autopf}\Moltage`, and may install to another administrator-writable local directory selected by the user. One supplied application image is retained as the packaging source and converted to the multi-size Windows icon used by the running application, packaged executable, and installer. The installer's Finished page offers a default-checked desktop-shortcut option without changing the permanent Start Menu shortcut. Packaging keeps the accepted entry and module graph unchanged, includes only the immutable `resources` tree, preserves the stable installer `AppId` and previous install directory during upgrades, and does not copy or delete `%APPDATA%\Moltage` state. At application startup, a bounded compatibility migration copies recognized non-secret files from the former application-data directory only when the corresponding Moltage destination is absent; it never overwrites a current file or removes the former directory. The build toolchain is isolated from the application runtime; server modules and executable locations remain runtime-discovered profile data rather than installer content.

## Conceptual areas and ownership

### Application

Cross-machine project access keeps two identities separate. The remote manifest preserves the server-profile UUID that created it, while `app/local_project_index.py` may record one explicitly approved current-machine binding. That approval is valid only for the exact `(project UUID, remote project path, current profile UUID)` tuple. Recovery consults it after the first confirmation so later refresh, geometry/restart preparation, continuation, and presentation-only orbital-Cube reads do not re-block the same project; another path or profile requires a new confirmation.

`app/tight_binding.py` resolves element/bond-type defaults plus exact atom/bond overrides into a complete local model, builds its real symmetric Hamiltonian, and evaluates single-site wide-band transmission. It refuses missing parameters instead of supplying chemistry-dependent defaults and caches the eigendecomposition while only lead/grid parameters change.

`app/server_profiles.py` retains deterministic non-secret profile and Slurm-location cache ownership. `app/project_planning.py` retains naming, initial project construction, and accepted anchor-based start-step advice. `app/imported_start.py` validates the exact imported two-contact context and binds an accepted Phase-2D applied result to durable cluster provenance; it does not infer chemistry or build electrodes. `app/local_project_index.py` owns the non-authoritative `last_seen_revision` cache, explicit current-machine profile binding, and persistent local recycle tombstones keyed by selected profile UUID plus project UUID; none rewrites historical remote identity. `app/project_presentation.py` adapts immutable recovery snapshots into one shared read-only display/sort record and does not copy or reinterpret workflow authority. `app/project_management.py` owns local recycle/restore orchestration, the shared active/unresolved deletion predicate, and the guarded permanent-delete use case outside Qt. `app/connection_service.py` preserves typed short-lived connection failures. `app/transport_convergence.py` proves normal initial Step-3 eligibility from managed recovery and exact electrode-application state, then creates the immutable three-file/hashes preflight bundle. `app/task_restart.py` owns exact current-task revalidation, strict recovery of pre-run settings and resources, and the one-shot exact-ID cancellation boundary; an ambiguous cancellation exposes no draft and is never retried. `app/project_submission.py` owns the accepted new-project submission path for Steps 1–3 plus narrow existing-project Step-2 and Step-3 continuation; edited Step 1–3 restart drafts use that same new-project path only after the source Job is durably terminal. `app/project_recovery.py` reconciles Step 3 through bounded scheduler/FHI-aims/AITRANSS-prerequisite evidence, owns the transient active-OOM observation and exact pre-cancellation revalidation, and reconciles Step 4 only after exact current-attempt scheduler, fatal, positive-marker, parseable-tcontrol, and result-grid evidence agree. Post-run tcontrol byte provenance is diagnostic rather than completion authority. Recycled identities are filtered only from the normal Project Manager result after authoritative discovery; that suppression is presentation state, not evidence that the remote project is absent. `app/transport_submission.py` remains the sole owner of resource-only Step-3 retry and explicit Step-4 preparation/submission, including an unchanged-geometry edited Step-4 attempt after durable user cancellation; all retain the submit-once/UNKNOWN boundary and durable manifest update. Application code contains no Qt widgets or Paramiko objects.

### Domain

`domain/tight_binding.py` owns the immutable orthogonal one-orbital model, real symmetric bond couplings, two distinct single-atom contacts, positive lead broadenings/numerical eta, a bounded start-inclusive/end-exclusive energy grid, and raw transmission samples. It does not assign physical parameter values or infer non-bonded couplings.

`domain/server_profile.py` owns immutable non-secret `ServerProfile`, structured `SlurmExecutionPreset`, optional verified `AitranssRuntimeConfiguration`, and optional single-recipient `SlurmMailSettings` validation. The profile's notification fields default to disabled/`None`; enabled values are normalized and validated locally before any remote operation. The preset includes exactly `AUTOMATIC` or `MANUAL` Slurm command-location policy and an optional/required safe absolute POSIX bin directory according to that mode. Runtime is canonical integer minutes, memory is canonical integer GB, and modules are ordered validated names. Legacy presets retain their ordered modules and launch command. Optional `RuntimeDiscoveryHints` hold partial directory/file constraints and explicit environment choices; `FhiAimsRuntimeConfiguration` holds the executable, launcher and resolved environment. AITRANSS can retain legacy modules or use its separate resolved environment. `RuntimeEnvironment` distinguishes Auto search requests from No setup, Modules and explicitly selected Setup script execution. A profile may remain without either runtime while its connection is saved and tested. `domain/calculation_project.py` owns stable project UUIDs, the exact four ordered steps, the distinct scheduler/scientific state values, fixed relative folders, revision, timezone-aware timestamps, first actual calculation step, and small per-step records. Schema-8 normal and direct Step-3 projects persist the same two-side generator provenance: geometry model and spacing, layer count, ordered standard lattice identities and mappings, separately ordered signed extension identities and mappings, apex, immutable reference corners, and independent accepted rolls. Schema 7 migrates with empty extension collections; schema 4–6 direct mappings migrate only through a bounded `LegacyAu59V1` decoder. Normal legacy projects without mappings carry proof-required state and cannot use mapping-dependent operations unless their historical ordering and contact evidence resolve uniquely. Schema-5 restart provenance stores only source project UUID, source step, exact Job ID, and source `geometry.in` SHA256. Its minimal Step-3/Step-4 attempt records preserve job, timestamps, terminal scheduler state, known failure reason, and distinct submit/output filenames across retries. `domain/electrode.py` owns immutable contact-site, exact preview, cluster mapping, and applied-result records; these contain no VTK objects. Domain code is independent of Qt, keyring, Paramiko, filesystems, scheduler commands, and scientific input bodies.

The execution preset's scheduler output value is either an intentionally incomplete empty string or one safe working-directory filename; it is never a directory or path, and script rendering refuses the empty state. `gui/remote_directory_dialog.py` belongs to Server Connections and selects only the profile's Remote project workspace. The existing short-lived connection boundary lists one requested directory at a time through SFTP and never scans, creates, selects files, or modifies remote paths.

For an LSF preset, `domain/server_profile.py` also owns optional safe absolute configuration, library, and server directories. Together with the scheduler command directory they form `LSF_ENVDIR`, `LSF_LIBDIR`, `LSF_SERVERDIR`, and `LSF_BINDIR`; they are invalid on a Slurm preset. New Manual LSF configuration requires all three additional fields at the GUI boundary. Older profiles load missing values as unresolved so Automatic preflight can rediscover and persist them without inventing a site value.

### Structure

Own structure-format input transformations through narrow extension dispatch. One explicit case-insensitive suffix authority contains `.xyz`, `.mol`, `.in`, `.next_step`, `.cube`, and `.cub`; both the file chooser and main-window local-file drag/drop route accepted paths through the same loader, with no content sniffing or parser fallback. Normal four-column XYZ remains strict and receives approximate inferred connectivity. MOL import accepts one connection-table V2000 record, preserves atom order/coordinates/elements, and supplies its explicit type-1/2/3 graph; V3000, SDF, aromatic/type-4 bonds, malformed indexes, self/duplicate bonds, truncation, and missing `M  END` fail explicitly. Local FHI-aims geometry does not add a parser: direct element species are passed to the same molecular-geometry parser without requiring `control.in`; an adjacent `control.in`, when present, supplies the existing alias mapping. A manually opened `.next_step` is parsed directly as one complete molecular geometry and never requests a companion `.in`; the separate server-backed optimized-structure path retains submitted/optimized ordered-chemistry validation. Unresolved aliases still fail explicitly. Cube import accepts one positive-grid-count scalar dataset, including ORCA/Gaussian negative-`NATOMS` orbital records whose dataset list contains exactly one identifier; true multi-dataset files remain explicit errors. ORCA coordinates use standard Cube Bohr units, while FHI-aims and unidentified producers require a workspace-local unit confirmation before conversion to angstrom. Scalar amplitudes remain in their source units. Scalar rows stream into one compact float64 buffer, and the renderer reverses VTK dimensions/affine columns to consume file order directly without a pointwise Python reorder. Arbitrary non-coplanar voxel axes and exact scalar-count validation remain supported. Display-order metadata and its `INFERRED`/`EXPLICIT` provenance are separate from the connected/not-connected `Connectivity` model. Structure also owns the reviewed BODR/Pyykko covalent-radius loader, the separate reviewed Charry Martinez-Tkatchenko free-atom van der Waals-radius loader, the approximate pairwise connectivity rule `distance <= multiplier * (radius_i + radius_j)`, and the anchor detector. The detector matches NCS, NH2, Pyridine-N, SMe, SH, Alkynyl-C, Cyano-N, and the conditional Dicyano-C site from element identities and supplied connectivity. A Dicyano-C center has exactly three non-Au neighbors, no H neighbor, and exactly two neighbors that independently satisfy the existing Cyano-N arm topology; the third neighbor's element and topology are otherwise unrestricted. Dicyano-C activates only when exactly two such groups exist in one structure. Their four Cyano-N candidates remain present and receive contextual placement only; one or more than two groups produce ordinary Cyano-N candidates without Dicyano-C candidates. Direct Au neighbors remain excluded from structural matching and recorded separately. These are topology rules and do not infer triple bonds, bond order, implicit H, charge, or valence.

### Visualization

Every `MoleculeViewerWidget` enables throttled atom-only hover by default. `MoleculeScene` renders the current atom with one camera-facing open ring plus an unpickable 1-based label; this applies unchanged when a signed Cube surface is visible. The local tight-binding workspace explicitly extends the same picker with its existing bond fallback and reuses two batched, unpickable parameter-label layers, populating at most one for the current atom or bond target. Leaving the canvas clears transient hover. Ordinary bond click-picking remains opt-in only while the Bond Couplings page is active, leaving every existing Geometry pick mode unchanged.

`visualization/view_preferences.py` owns one immutable application-session molecular-view state: relative bond thickness, per-element RGB overrides, element-label visibility, visual-only H hiding, and the current theme-owned atom-feedback palette. The base glyph input may contain only visible atoms, but its selection array continues to carry authoritative original atom IDs. The bond input may omit H-incident strands, but retained cells continue to carry authoritative Connectivity-edge IDs and unchanged display-order metadata. H filtering also suppresses H labels and feedback rings/shells while retaining complete coordinates, elements, edges, measurements, and torsion edit state for restoration. Per-atom symbol and atom-number actors are camera-facing and unpickable. Applying preferences rebuilds only VTK presentation data, preserves the active camera, and never re-reads geometry. `structure/atom_editing.py` owns deterministic single-atom deletion/reindexing and element replacement over the supplied current Connectivity; neither operation infers a new graph.

`visualization/orbital_surface.py` owns the Cube-only signed isosurface layer. It caches Flying Edges output, applies a fixed polygon budget only when necessary, and therefore does not extract a new mesh during camera motion or color/opacity/lighting changes. Positive and negative contours use independent workspace-local colors. The only styles are opaque and fixed 50% semi-transparent; isovalue zero hides the layer. Orbital-only ambient balance and lobe-brightness intensity are independent bounded `0.00`–`1.00` controls with defaults `0.90` and `0.82`; intensity scales the effective lookup-table colors so every change is visible, while ambient balances fill and directional shading. Phong shading reuses existing normals and adds white specular highlights with strength `0.30` (`0`–`1`) and shininess `32` (`1`–`128`). Reflected grid-to-world transforms reverse only displayed triangle winding so two-sided lighting agrees with the transformed normals; points, normals, scalar values, and polygon counts remain unchanged. No shadows, ambient occlusion, mesh subdivision, or molecular-material changes are added. An explicit recommended-material button previews Ambient `0.55`, intensity `0.95`, specular `0.30`, and shininess `32` without touching isovalue/colors/opacity. `app/user_view_preferences.py` atomically persists those four accepted values under the per-user application-data root; old two-value files retain their saved lighting and receive only the new material defaults, while isovalue, colors, and opacity remain workspace-local. Generic linker/contact-Au highlight shells are populated only while the compatible Au Tool is visible; Cube never displays them. The actor is unpickable and Cube Geometry workspaces are read-only for structure/workflow editing while retaining camera, reset, atom inspection, and measurement behavior.

Own reusable molecular rendering through PySide6 and direct VTK integration. `MoleculeScene` retains one GPU glyph pipeline for all base atoms, one line/tube pipeline for all supplied logical bonds, one translucent glyph pipeline shared by primary/secondary shells and the distinct amber temporary-measurement shells, and one generic glyph pipeline for all visual-only preview atoms. The viewer can project cached preview targets carrying opaque identities and returns only the selected token; pointer coordinates never become geometry, and the unpickable preview actor remains presentation-only. A logical order 1/2/3 edge becomes one/two/three parallel strands using a deterministic camera-independent least-parallel-axis cross product; every strand carries the same Connectivity-edge selection ID, including selected-bond highlighting. It additionally batches all explicit distance dashes and persistent manual-angle A-B/B-C guides in one actor and all 3D angle arcs in one actor, with reusable billboard labels. Distance labels use their projected guide direction plus a stable perpendicular display offset, while three fixed billboard actors provide temporary 1/2/3 pick order without becoming measurement records. Temporary scientific-placement annotations, stable-ID manual-measurement annotations, temporary pick feedback, selected-bond torsion actors, and the six-atom electrode-surface overlay have separate ownership. The surface overlay uses distinct Left/Right colors and independent 1-based labels and is cleared on structure replacement without changing coordinates or Connectivity. Rendered bond cells carry their deterministic Connectivity-edge index; rotation picking never creates a cursor-nearest atom pair. The torsion visual comprises a semi-transparent selected bond, circular arrow, fixed and movable black radial rays, signed relative-angle arc/value, and an offset thick arrow toward the rotating endpoint component. `visualization/bond_torsion.py` owns the connectivity bridge analysis, endpoint groups, Rodrigues rigid rotation, signed-angle normalization, and linear 0.30°/pixel mapping without importing Qt or VTK. `visualization/measurements.py` retains immutable measurement records and Cartesian measurement math plus snapshot/index-remap operations. `MoleculeViewerWidget` owns Qt embedding, rendering, trackball-camera interaction, atom/bond/gizmo picking, exclusive torsion drag gestures, and full redraw while preserving the camera. `gui/geometry_history.py` supplies the five-level per-workspace linear history for coordinates, atom identities/count, Connectivity, display orders, measurements, and applied-geometry state.

For Au(111) extension hover, `junction/electrode_lattice_interaction.py` derives exact predicted-neighbor endpoints from unchanged Phase-2 lattice topology and two same-layer basis vectors from the current rigid side frame. `MoleculeScene` receives only those current-world visual facts and uses dedicated unpickable actors for dashed neighbor lines and a finite triangular plane/grid with per-vertex outward alpha fade. The rendered guide is never read back as lattice, bond, collision, or click authority and is cleared with the transient ghost lifecycle.

Atom feedback adds one batched line pipeline for every open ring plus three batched label channels for density subset 1, density subset 2, and the current hover atom. Density-fragment membership has a dedicated ring API and therefore does not repurpose Au/contact or measurement shells. Ring geometry is rebuilt only when membership, hover, atom coordinates/visibility, theme colors, or camera orientation changes; it never enters molecular data.

The torsion refinement adds one reusable pickable black sphere at the movable radial-ray endpoint. The ordinary signed-angle value is a VTK billboard rendered with the moving 3D scene; clicking it temporarily replaces that value with one opaque white Qt numeric editor at the same projected position. The sphere uses pointer direction around the actual bond axis while the other drag targets retain linear pixel gain. Every path still feeds the same torsion controller, and none changes Connectivity or camera state.

### Junction

Own deterministic contact-Au and electrode construction behavior. The accepted existing anchor paths in `junction/au_placement.py`, `junction/steric_orientation.py`, and `junction/apply_placement.py` remain unchanged. Dicyano-C reuses the existing cone and hard-steric machinery with resource defaults C–Au `2.10 Å` and third-neighbor–C–Au `111°`, minimizing the difference between its two Au–C–N angles. Cyano-N sites inside an activated pair retain their Cyano-N identity but use contextual Au–N `2.00 Å` / C–N–Au `121°` defaults and choose the largest displacement along the normal of the local two-CN-arm plane. A two-site special proposal requires a hard-sterically-valid opposite-side pair and keeps deterministic clearance/separation ordering. `domain/au_pyramid.py` generates `MoltageAuPyramidV1` for 2–10 layers from deterministic integer lattice identities at the project spacing `2.88372 Å`; the apex is `(0,0,0)`, the ordered outer corners are `(n-1,0,0)`, `(0,n-1,0)`, `(0,0,n-1)`, and connectivity is lattice-derived. `domain/au_lattice_extension.py` keeps signed extension identities separate, reconstructs each side's exact identity-anchored frame, and owns finite seed/boundary candidate rules without scientific radius inputs. `junction/electrode_lattice_extension.py` applies the shared validation pipeline and immutable append operation; it contains no viewer interaction. `junction/electrode_lattice_interaction.py` maps those canonical identities one way into each current rigid side frame, retains every Phase-2 candidate, and classifies current addability with the existing Au clearance and non-Au vdW radius-sum semantics. It fresh-validates identity and current geometry before preparing an add; it neither derives lattice sites from XYZ nor persists transient availability. `junction/electrode_builder.py` recognizes eligible contacts only through detected anchors with exactly one attached Au, aligns each generated principal axis to `binding atom -> contact Au`, and performs the existing deterministic coarse/refined joint roll search while retaining independent Left/Right orientations. A preview stores exact coordinates, generator connectivity, identities, layer count and mappings. Application consumes that preview without recalculating geometry, preserves every Step-2 atom/bond, reuses each contact Au as local apex 0, and appends the generated non-apex atoms in deterministic side/local order. `junction/electrode_surface.py` reconstructs and validates full generated membership plus unchanged standard corners from persisted provenance rather than suffixes, PCA, convex hulls or Au clustering. The former A/B coordinate resources and fixed active counts are not runtime inputs.

### FHI-aims

Own FHI-aims-specific transformations and pure input materialization. `aims/species_library.py` validates already acquired species-definition text and exposes it through an in-memory provider; it does not read local packaged defaults or perform remote I/O. New Step-1, Step-2, Step-3, density, and standalone export inputs begin as immutable plans. The application layer acquires only their exact `<NN>_<Element>_default` requirements from the selected saved server profile's canonical root, then materializes complete inputs before any remote project mutation or local export write. `aims/orbital_cube.py` owns the six canonical frontier labels, positive 1-based absolute state numbers, deterministic filenames, and optional grid spacing shared by the writers and strict reverse parser. Step 1 defaults to `homo-2`, `homo-1`, `homo`, `lumo`, `lumo+1`, and `lumo+2`; Step 3 accepts absolute state numbers only. A blank spacing emits no grid directive and leaves FHI-aims defaults untouched. An explicit spacing uses the long-supported `cube origin` plus three axis-aligned `cube edge` records around the actual molecular bounds with the documented 14-Bohr cluster padding; it does not emit the newer `cube edge_density` shorthand, preserving compatibility with supported legacy FHI-aims releases. The Step-3 transport-convergence settings/control/bundle modules remain separate because relaxation, force convergence, optimization output, and dispersion are not Step-3 concepts. They default to `tight` and fix `output aitranss`, `KS_method serial`, and `restart aims.restart`. `aims/input_parser.py` recovers editable settings solely from the embedded species blocks in exact historical `geometry.in`/`control.in` pairs; no server or local library is consulted, and unsupported or ambiguous input fails instead of guessing. `aims/recovery.py` remains the Step-1/Step-2 optimization recovery owner. `aims/transport_evidence.py` owns exact Step-3 normal-termination, atom-count, spin-mode, required-file, NSAOS-header, and observed timeout-tail evidence parsing from bounded reads. Scheduler submission and byte-preserving retry do not alter authoritative `geometry.in` or `control.in` bytes.

The Step-1 orbital recovery and display boundary is **fully accepted and frozen**. `app/project_orbital_cube.py` owns its presentation data. Recovery performs one nonrecursive directory listing and bounded metadata checks against only the canonical filenames actually requested by `control.in`; it neither scans the project nor downloads Cube payloads. Its immutable binding carries the exact profile, managed project, authoritative recovered Step-1 structure, catalog, and rebind decision into either the editable recovery workspace or the read-only Step-1 output workspace opened from a status indicator. A later explicit click reloads the managed project identity and successful Step-1 state, revalidates the selected file metadata, streams exactly that file to a temporary local path, parses FHI-aims Cube header coordinates as Bohr, and requires its ordered atoms and converted coordinates to match the authoritative recovered structure within output precision. The presentation layer accepts that reference unchanged or through the explicit `AppliedAuPlacement` source-to-result map, including validated terminal-H removal; it never derives orbital identity from the Au-modified structure. Only the scalar field crosses into rendering. The temporary file is removed, and no project, molecule, connectivity, Au placement, or calculation-setting state is mutated.

### ORCA

`orca/catalog.py` owns the reviewed 5.0.x/6.0.x/6.1.x capability matrix and exact structured tokens; `orca/settings.py` owns immutable optimization/frequency settings, electron-parity validation, documented def2 element coverage and stage-specific resources. `orca/input_writer.py` renders deterministic UTF-8/LF Cartesian inputs with the same coordinate representation used by the FHI geometry writer. `orca/batch.py` reuses only validated scheduler site/resource helpers and renders one direct absolute ORCA driver invocation with `%pal nprocs` equal to scheduler task slots. `orca/evidence.py` keeps normal termination, optimization convergence, exact ordered XYZ validation, frequency completion, Hessian dimensional evidence and ORCA-reported imaginary annotations distinct. `app/orca_submission.py` owns managed upload/hash/submit-once orchestration; the ORCA branch in `app/project_recovery.py` owns scheduler reconciliation and hash-bound scientific recovery. ## Infrastructure boundaries

The remote-executor protocol supports bounded Slurm/AITRANSS discovery and verification, status commands, SFTP file access including bounded heads/tails, and complete command results while Paramiko remains isolated inside its adapter. Discovery, `squeue`, `sacct`, and executable verification are not job submissions; absolute `sbatch --parsable <verified-script>` retains the submit-once/unknown-outcome boundary for Steps 1–4. The one narrow cancellation path reloads the authoritative manifest, verifies the same project UUID/current Step-3 Job/script/output, rechecks exact `RUNNING` plus exact OOM evidence, and then dispatches exactly one `<verified-bin>/scancel <exact-job-id>`. A known zero means request accepted only; a normal nonzero changes nothing; ambiguous post-dispatch loss is `UNKNOWN` and is never retried. A terminal race sends no `scancel` and reconciles normally. Local recycle and permanent deletion share one operation-safety predicate: persisted `QUEUED`, `RUNNING`, or `UNKNOWN`, typed accounting-pending/unresolved scheduler observations, and a matching live submission block deletion before any tombstone, credential lookup, or remote mutation. `SCHEDULER_COMPLETED` is scheduler-terminal and therefore remains deletion-eligible, subject to the existing permanent-only open-workspace and exact-path guards, even though its scientific result is unresolved. Permanent deletion verifies the selected profile UUID, exact project UUID, unchanged manifest/revision, direct-child path below the configured workspace root, nonempty basename, and non-symlink root, then dispatches one exact safely quoted delete without wildcard. Confirmed absence alone removes local entries. A definite failure leaves them intact; ambiguous loss after dispatch, or transport loss during the absence check, reports `Deletion outcome unknown. Reconnect and Refresh.` and never repeats deletion automatically. Retry and Step 4 use new script/output names and new-file-only uploads; no accepted input or prior attempt output is overwritten. Optional Slurm-native mail adds no probe or network call. No automatic or generic cancellation, periodic Step-3 polling, notification center, cloud-filesystem, backend registry, dependency-injection framework, or plugin system was added.

Each project is bound to one stable server-profile UUID. Multiple profiles may exist and be renamed independently. Site-specific execution values are representable as profile data but are not global defaults or scientific settings.

## Scientific and workflow invariants

- Scientific behavior comes from explicit user input, configuration, approved templates, reference files, and documented rules.
- Phase 1C XYZ connectivity is approximate, geometric, and limited to connected/not connected; it does not infer bond order, valence, or chemical identity. MOL V2000 connectivity is explicit input, not Phase-1C inference.
- Phase 1D-R anchor detection consumes element identities and supplied connectivity only; it preserves Au directly connected to recognized binding atoms but does not infer electrode role, aromaticity, bond order, implicit H, charge, valence, or placement geometry.
- WF-R1 direct-Step-2 eligibility requires exactly two recognized linker termini with one directly attached contact Au each and no other Au. It accepts either source-resident contacts or a current state produced by accepted viewer application, including two sites applied together or sequentially, whose latest applied atom identity and bond topology still match; it is not an Au-count, filename, distance-only, or MOL-bond-order heuristic. Direct Step 3 remains source-provenance-only and additionally requires the exact accepted two-electrode applied result plus operation-local confirmation that the imported molecule–Au geometry was already appropriately optimized, so viewer-added contacts cannot skip Step 2.
- Phase 1E-A-R2 placement remains frozen: proposal coordinates are authoritative virtual metadata. Phase 1E-B application copies those exact floats without lookup or geometry search, simultaneously applies recorded removals, preserves surviving source order, appends new Au deterministically, and transforms connectivity explicitly. The original loaded geometry remains unchanged; Bond Detection regenerates only inferred-source workspaces and never discards an explicit MOL graph or its current working state.
- Phase 2D electrode proposals are authoritative immutable previews. Existing optimized contact Au coordinates/indexes remain exact as cluster apices; the selected 2–10 layer generator supplies all other atoms, lattice identities and mapped neighbor edges. The default six-layer pyramid is Au56 and appends 55 atoms per selected side. Two-cluster Done consumes the displayed proposal without alignment, roll, or transform recalculation; reopening the recovered Step-2 project restores its optimized source.
- Phase 3A Step-3 geometry is the exact current two-cluster working structure by normal managed-session or validated imported-start provenance, including coordinate-only torsion edits made after electrode application. Atom index/element identity and immutable electrode mapping remain mandatory. Submission never regenerates electrodes, reruns roll selection, reloads Step 2, or infers eligibility from Au count. Both entry paths use the same frozen generator and control, containing no geometry relaxation, force convergence, optimization output, or dispersion directive.
- Phase 3B retry preserves the exact accepted Step-3 `geometry.in` and `control.in` hashes, leaves `aims.restart` untouched, preserves every prior script/output/job record, and permits only explicit resource changes before one new `sbatch`. Editable values start from the hash-verified authoritative current-attempt script; current profile environment/launch, frozen fail-fast, and `END,FAIL` mail remain the renderer authority.
- Phase 3B surface indices come only from schema-8/validated-legacy atom mappings and immutable standard lattice-corner identities. Generated electrode membership includes separately persisted, replay-validated extensions; extension atoms never replace a reference corner. Production code does not hardcode final 1-based numbers or infer identities from coordinates; ambiguous legacy evidence fails explicitly.
- Phase 3B `tcontrol` derives atom count from FHI-aims output, NSAOS from bounded orbital-file headers, and spin-specific prerequisite names from the frozen submitted control. Valid user edits never mutate the immutable automatic proposal.
- UI-M1 measurements are session-local viewer annotations only. They store current zero-based atom indices and completed numeric values, do not add connectivity edges or alter structures/projects, and are cleared rather than remapped whenever the displayed structure is replaced.
- UI-M2 eligibility uses every existing Connectivity edge without bond-order, valence, aromaticity, length, or element classification. An edge is rotatable only when its temporary removal separates its two endpoints, equivalently increasing the complete graph's component count by exactly one. Other pre-existing disconnected components remain fixed and do not participate in endpoint-group sizing.
- UI-M2 replaces only current working Cartesian coordinates. It preserves exact atom ordering and Connectivity membership, never re-infers bonds, and does not save files, change manifests, submit work, or modify frozen Step-3 rules. Bond-order filtering is deferred.
- UI-R5 bond order is display-only metadata. Imported MOL orders survive coordinate-only edits and explicit valid reindexing; generated-electrode/Au-related new edges are visual single bonds. The metadata never enters FHI-aims/AITRANSS inputs, project manifests, or remote submission.
- Visualization preserves stored atomic centers and renders the supplied connectivity without recomputing or chemically interpreting it.
- Required missing input fails explicitly; no value, file, algorithm, or path is silently substituted.
- Contact Au atoms added before optimization are not fixed; they optimize with the molecular structure.
- Scheduler completion is not equivalent to FHI-aims technical success or scientific convergence.
- Total system charge is independent of per-atom `initial_charge`, which is only an initial-density guess. Collinear spin requires an explicit nonzero per-atom moment or a deliberately supplied nonzero uniform per-atom default; optional `fixed_spin_moment` is a separate total 2S constraint.
- Every geometry species name has exactly one corresponding control species block. Per-atom accuracy aliases never modify chemical element identity in `MolecularStructure`.
- Anchor recognition and geometry remain anchor-specific without duplicating the overall workflow.

## Structural hazards to avoid

- GUI/domain coupling or scientific logic embedded in event handlers;
- circular dependencies;
- generic dumping-ground files such as `utils.py`, `helpers.py`, `misc.py`, or `common.py`;
- god files and unrelated responsibilities;
- one-file-per-trivial-operation fragmentation;
- speculative abstraction and unnecessary plugin frameworks;
- patch-on-patch conditionals that conceal a violated model or invariant.
