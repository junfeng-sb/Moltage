# 13. 项目管理器

[返回手册目录](README.md)

## 13.1 用途和入口

**入口：** `Projects > Project Manager...`

Project Manager 用于管理已经提交的计算、查看当前状态，并执行各工作流允许的后续操作。它会读取所选服务器配置下的项目；只有用户明确发起刷新时，才会核对调度器和外部程序状态。

## 13.2 窗口控件

| 控件 | 用途 |
| --- | --- |
| **Server** | 选择要检查其远程工作区的已保存配置 |
| **Refresh / Stop** | 启动完整查找与状态核对，或立即停止当前刷新会话 |
| **Sort** | 按 File name、Submission date 或 Step type 排序 |
| 排序方向控件 | 反转完整且确定的排序顺序 |
| 视图选择器 | 在 Details、Compact 和 Tiles 之间切换，不触发远程操作 |
| Recycle Bin 控件 | 显示所选配置中已在本地移入回收站的项目 |
| 项目列表 | 按稳定 UUID 选择一个项目或任务 |
| 消息区 | 显示所选操作或状态的说明 |
| 上下文操作区 | 仅显示当前工作流和状态允许的操作 |
| **Close** | 隐藏非模态窗口；计算继续运行 |

Project Manager 是非模态窗口。隐藏窗口不会停止状态刷新或远程作业。退出应用程序会与仅用于状态查询的刷新会话分离，但不会取消计算。

## 13.3 刷新行为

完整刷新和单项目 **Refresh Status** 都有 60 秒的整项 UI 超时，其中包括连接和远程读取。

- 刷新期间，**Refresh** 会变为 **Stop**。
- **Stop** 会立即恢复本地控件，并忽略该刷新会话之后到达的结果。
- 停止或超时都不会发送 `scancel` 或 `bkill`。
- 超时仅表示刷新未完成，不表示计算本身超时。
- 界面会保留此前显示的状态。
- 用户可以立即发起新的显式刷新，旧会话的迟到结果不会覆盖新状态。
- 刷新停止前已经写入项目记录的状态不会回滚。

## 13.4 项目显示方式

三种视图均使用同一份项目状态记录。

| 视图 | 内容 |
| --- | --- |
| **Details** | 多行显示工作流状态、调度器/Job 证据、程序或科学状态消息和阶段指示灯 |
| **Compact** | 单行显示远程项目名称和阶段指示灯 |
| **Tiles** | 固定卡片显示不含日期的名称、项目提交日期和阶段指示灯 |

切换视图或排序方式只影响本地显示。选择仍绑定项目 UUID，不会发起 SSH 查询或写入项目清单。

排序定义：

- **File name**：按远程目录名进行自然、不区分大小写的排序。
- **Submission date**：使用项目最早的真实阶段提交时间；重试不会让旧项目被误认为新项目。
- **Step type**：根据项目状态判断当前最高的活动或已到达阶段，而不是解析文件名。

新打开窗口时默认按 Submission date 从新到旧排列。

## 13.5 状态指示灯

### FHI-aims/AITRANSS 项目

始终按以下顺序显示四盏指示灯：

1. 分子优化
2. 分子–Au 优化
3. 输运收敛
4. Transmission

### ORCA 项目

只显示两盏指示灯：

1. ORCA 优化
2. WBL transmission

可选的频率分析不会增加第三盏指示灯。

### 电子密度差任务

三盏指示灯表示同一个调度器作业中依次运行的三个组成部分：

1. Total
2. Subset 1
3. Subset 2

### 颜色和符号

| 外观 | 状态 |
| --- | --- |
| 绿色实心 | `SUCCEEDED` / 已通过科学证据恢复的组成部分 |
| 灰色实心 | `SKIPPED`；电子密度差任务被取消时也使用一种不同的灰色终态显示 |
| 红色实心 | `FAILED` |
| 空心 | `NOT_STARTED` |
| 黄色实心 | `QUEUED`、`RUNNING`、`SCHEDULER_COMPLETED` 或 `UNKNOWN` |
| 带 `?` 的黄色 | 终态或程序信息仍未确认；工具提示保留具体状态 |

调度器返回 `COMPLETED` 不会自动点亮绿色。相关程序输出、哈希、几何/结果证据和工作流专用成功条件都必须通过。

## 13.6 指示灯的左键和右键操作

- **左键单击**：打开该阶段可用的只读输入/输出几何菜单；如受支持，也可打开相应的已完成结果。
- **右键单击**：只有当该阶段正是当前活动任务且状态允许时，才显示任务操作。

对于具有已保存十进制 Job ID，且当前处于 `QUEUED` 或 `RUNNING` 的 FHI Step 1–4 任务，右键菜单可提供 **Abort Task and Create Restart Draft...**。Moltage 会在发送一次精确取消命令前，重新验证项目、阶段、Job、输入哈希和调度器状态，不会根据任务名称猜测目标。

## 13.7 常见上下文按钮

| 按钮 | 用途和可用条件 |
| --- | --- |
| **Open / Recover** | 刷新或恢复所选项目适用的几何/结果证据 |
| **Refresh Status** | 只核对所选项目 |
| **Kill Job** | 对严格限定的 Step 3 内存不足场景，在重新验证对应 Job 后明确请求取消 |
| **Cancel ORCA Job...** | 取消经过验证且仍处于活动状态的 ORCA 优化 Job |
| **Resubmit Optimization...** | 从 ORCA 项目打开结构化设置并创建新项目；旧 Job 若仍活动会先被取消 |
| **Resubmit Step 3...** | 对经检查的 Step 3 超时或内存不足失败重试；资源可编辑，科学输入不可变 |
| **Retry with explicit self-energy...** | 准备严格限定的 AITRANSS 界面重叠重试 |
| **View Transmission** | 打开科学状态成功且当前可解析的 FHI/AITRANSS 结果 |
| **View WBL Transmission** | 打开已完成的 ORCA WBL 结果 |
| **Delete Project...** | 将符合条件的终态项目移入本地回收站，或明确请求受保护的远程永久删除 |
| **Restore** | 删除所选本地回收站标记；之后需正常 Refresh 才会重新发现远程项目 |
| **Back to Projects** | 离开 Recycle Bin 视图 |
| **Close** | 隐藏 Project Manager |

与当前工作流无关的按钮会被隐藏，而不是以容易误解的禁用状态出现。尤其是 ORCA 项目不会显示 Step 3 重试、显式 self-energy 重试或 FHI transmission 操作。

## 13.8 Open / Recover

恢复流程会区分以下结果：

1. 连接/查询是否成功；
2. 调度器状态；
3. 外部程序是否正常结束；
4. 科学计算是否收敛/完整；
5. 是否有可显示的几何或结果。

例如：

- FHI Step 1 作业只有在具有经审核的正常终止证据以及化学一致、有效的 `geometry.in.next_step` 时，才会成为成功状态。
- ORCA 优化要求调度器成功、ORCA 正常终止、优化收敛、输入哈希绑定，以及原子顺序有效的最终 XYZ。
- AITRANSS Step 4 要求其成功标记、可解析的活动 `tcontrol` 和完整有效的 transmission 网格。

绘图渲染错误不会反向改变科学状态已成功的项目。

## 13.9 重启草稿

精确取消请求被接受后，Moltage 会把运行前几何作为当前会话中的可编辑草稿打开。在显式执行 **Refresh Status** 并确认源 Job 已进入终态前，提交仍保持锁定。

- Step 1/2 草稿恢复结构化优化设置。
- Step 3 草稿恢复固定几何的收敛设置。
- Step 4 草稿恢复 `tcontrol`、单进程资源和对应的 Step 3 输运几何。
- Step 3/4 草稿只允许修改坐标；原子顺序、元素和电极归属必须保持不变。

编辑后的 Step 1、2 或 3 草稿会创建新项目并记录重启来源信息，绝不会覆盖源项目。如果 Step 4 草稿的坐标发生变化，则必须通过新的 Step 3 项目返回流程，因为旧矩阵已不再有效。

## 13.10 Step 3 资源重试

**Resubmit Step 3...** 只用于经审核的超时或内存不足失败。对话框从通过哈希验证的当前尝试脚本中恢复资源值。根据调度器类型，它会显示适用的节点数、任务数、每任务 CPU、最长运行时间、内存、OpenMP 线程和执行模型摘要。

- 几何和 `control.in` 哈希保持不变。
- 如果存在 `aims.restart`，会保留该文件。
- 以前的脚本、输出和 Job 记录会保留。
- 新尝试使用新的 `retryNN` 脚本和输出文件名。
- Moltage 不会自动计算应增加多少内存。
- 每次仍至多提交一次；无法确认的提交结果会记为 `UNKNOWN`，不会自动重试。

## 13.11 精确取消边界

取消始终需要用户明确操作。调度器取消命令成功只表示取消请求已被接受。之后请运行 **Refresh Status** 获取调度器终态。

如果命令发出后连接中断，Moltage 会报告结果未知，并且不会自动发送第二次取消命令。如果作业恰好已进入终态，则不会发送取消命令，而是正常核对状态。

## 13.12 回收与永久删除

### Move to Recycle Bin

默认的 **Delete Project...** 操作只创建本地回收站标记：

- 不建立 SSH 连接；
- 不取消调度器作业；
- 不远程移动或删除；
- 远程项目本身保持完整；
- 该项目在此配置的正常列表中被隐藏。

**Restore** 只删除本地标记。之后刷新时，如果远程项目仍存在，就会重新发现它。

### Delete Permanently

勾选永久删除服务器文件的选项，会把操作改为不可逆的精确路径删除。只有同时满足以下条件时才可使用：

- 没有任何阶段/任务处于 queued、running、unknown 或 unresolved；
- 没有匹配的活动提交；
- 本地没有仍打开的相关工作区；
- 服务器配置、项目 UUID、项目清单版本和路径仍完全匹配；
- 目录是配置的远程工作区下一级的直接子目录；
- 目标不是符号链接，且 basename 非空。

Moltage 只发送一条经过安全引用、针对精确根目录且不含通配符的删除命令。如果传输中断导致结果不明，会报告 **Deletion outcome unknown. Reconnect and Refresh.**，绝不会自动重复删除。

## 13.13 跨计算机项目绑定

项目会记录创建时使用的服务器配置 UUID。从另一套 Moltage 安装访问该项目时，Moltage 会询问是否把对应的远程项目 UUID/路径与当前选择的本地配置关联。确认信息只保存在当前计算机上，并且仅适用于这一组合，不会修改远程项目。换用其他配置或路径时需要单独确认。
